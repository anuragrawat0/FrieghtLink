# FreightLink

FreightLink uses a Node.js 24 npm workspace with a Next.js frontend, a Fastify API and PostgreSQL. The [Phase 0 contracts](docs/CONTEXT.md) define the business modules.

## Run FreightLink

Copy `.env.example` to `.env`. Use a URL-safe `POSTGRES_PASSWORD` and use the same password in `DATABASE_URL`, which points to `localhost:5433`. Set `JWT_SECRET` with a value generated by `node -p "require('node:crypto').randomBytes(32).toString('hex')"`. To create a demo admin in development, set both `DEMO_ADMIN_EMAIL` and `DEMO_ADMIN_PASSWORD`. Startup applies Prisma migrations, runs the optional seed, and then starts Fastify. The seed never resets an existing admin's password. It logs a warning and skips seeding when `NODE_ENV=production`, including in the full Docker stack.

### Full Docker stack

```sh
docker compose up --build
```

Compose starts PostgreSQL, then Fastify, then Next.js. PostgreSQL is published at `localhost:5433`. The API container connects to `db:5432` on the Compose network. The `postgres_data` and `uploads_data` volumes persist database records and uploads.

### Local development with hot reload

Use Node.js 24. If switching from the full Docker stack, run `docker compose stop api web` to free the application ports.

```sh
npm ci
npm run dev
```

The dev command starts PostgreSQL and waits for it to be healthy before launching the API and web together. Both read the root `.env`. Press Ctrl+C to stop both application servers. A relative `UPLOAD_DIR` resolves from the API workspace. To change the database's published port, update both `POSTGRES_PORT` and the port in `DATABASE_URL`. If you change the application ports, update `WEB_ORIGIN` and `NEXT_PUBLIC_API_ORIGIN` to match. Use `PORT` for the local API, `API_PORT` for its Docker host port, and `WEB_PORT` for the web in either mode.

Open [FreightLink](http://localhost:3000). [API readiness](http://localhost:3001/api/v1/health) checks the PostgreSQL connection. Socket.IO runs at `/socket.io` on the API port.

## Run tests

Run `npm test` from the workspace root for unit tests. For database integration tests, set `TEST_POSTGRES_PASSWORD` and use the same URL-safe password in `TEST_DATABASE_URL`. Keep the database and user named `freightlink_test`.

```sh
docker compose -p freightlink-smoke -f compose.test.yaml up -d --wait
npm run test:db
docker compose -p freightlink-smoke -f compose.test.yaml down -v --rmi local
```

The test Compose stack uses a separate PostgreSQL service with temporary storage. The integration runner requires an explicit test URL, rejects the development database name as a test target, and applies migrations to the test database before running. The suite deletes only its own fixtures and closes its connections during teardown.

## Register modules

Add each business module as a Fastify plugin in [`apps/api/src/modules/index.ts`](apps/api/src/modules/index.ts). Its paths are mounted under `/api/v1`. Infrastructure already supplies `app.prisma`, `app.io` and the shared authentication plugin.

- `app.auth.signAccessToken(userId)` issues the access token. `app.auth.verifyAccessToken(token)` verifies it and returns the claims. `app.auth.authenticateAccessToken(token)` also resolves the current user in PostgreSQL and is shared with Socket.IO. Use this single token implementation in every module.
- Use `onRequest: app.authenticate` for authenticated routes. This attaches the current public user fields to `request.user` before request validation. For a route-level role check, also use `preHandler: app.authorize("SHIPPER")`.
- Apply `config: { rateLimit: authRateLimit }` to each future registration and login route, importing `authRateLimit` from [`plugins/rate-limit.ts`](apps/api/src/plugins/rate-limit.ts).
- Use `AppError` from [`shared/errors.ts`](apps/api/src/shared/errors.ts) for contract errors. Map operation-specific database conflicts in the module that owns the operation.
- See the [module instructions](docs/CONTEXT.md#how-to-add-a-module) for transactions, socket events, uploads, and raw webhook bytes. Frontend modules use `apiFetch`, `setAccessToken`, `connectSocket`, and `disconnectSocket` from `apps/web/src/lib`. Clear the token and disconnect the socket on logout.

## Known limitations

- Docker can present multiple callers to Fastify under one shared IP, so they share the same registration or login rate-limit bucket. Each IPv6 address has its own bucket, so a caller rotating IPv6 addresses can use separate buckets.
